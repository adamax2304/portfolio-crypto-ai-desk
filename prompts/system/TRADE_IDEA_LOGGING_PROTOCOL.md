# Trade Idea Logging Protocol

How to record every trade idea the desk generates, including the ones that don't become trades.

---

## What gets logged where

| Tier / status | Folder | When to log |
|---|---|---|
| A-tier | `obsidian_vault/11_Trade_Journal/Potential_Trades/` | **Always**, immediately when the report fires |
| B-tier (actionable or close to trigger) | `obsidian_vault/11_Trade_Journal/Potential_Trades/` | Always |
| C-tier with clear trigger condition | `obsidian_vault/11_Trade_Journal/Watchlist_Ideas/` | When there's a concrete activation condition |
| C-tier (low conviction, no trigger) | (skip) | Only log if pattern-relevant |
| Rejected (educational) | `obsidian_vault/11_Trade_Journal/Rejected_Ideas/` | Only if rejection teaches something or pattern repeats |
| Executed (user took the trade) | `obsidian_vault/11_Trade_Journal/Executed_Trades/` | When user confirms entry |
| Review (after close) | `obsidian_vault/11_Trade_Journal/Reviews/` | Within 24h of close |

## Filename format

```
YYYY-MM-DD_SYMBOL_MODE_DIRECTION_TIER_SCORE.md
```

Examples:

- `2026-05-23_SOL_intraday_LONG_A_82.md`
- `2026-05-23_WIF_scalp_LONG_B_74.md`
- `2026-05-23_PEPE_scalp_WATCHLIST_C_61.md`
- `2026-05-23_INJ_intraday_REJECTED_44.md`

Use the symbol's ticker without the `/USDT` suffix in the filename for readability.

## Required fields in every potential trade entry

- date/time (UTC)
- symbol (full ccxt form e.g. `SOL/USDT`)
- mode (`scalp` / `intraday` / `swing`; for invest fallback record both `requested_mode` and `actual_mode`)
- direction (`long` / `short` / `watchlist` / `no_trade`)
- tier (`A` / `B` / `C` / `rejected`)
- score (final_score from ScoringAgent)
- confidence (`high` / `medium-high` / `medium` / `low`)
- data_confidence (`high` / `medium` / `low`)
- exchange focus (binance / bybit / mexc)
- market regime (label + risk_mode)
- thesis (one paragraph from `TradeIdea.thesis`)
- entry zone (entry_low – entry_high)
- invalidation (timeframe close beyond X)
- targets (TP1 / TP2 / TP3)
- risk/reward (rr_to_tp1)
- technical evidence (trend, setup_quality, ATR, support/resistance)
- derivatives evidence (funding, OI change, interpretation)
- Telegram/news evidence (verification status, attention stage, source list)
- narrative / crowd attention (best narrative status + crowd stage)
- counter-thesis (CriticAgent.counter_thesis + contradictions)
- no-entry conditions (avoid_conditions)
- monitoring checklist (what_to_monitor)
- source/report reference (path to the generating report)
- caps active (cap_reasons)
- current status (see below)

## Status field

Allowed values:

- `Potential` — generated by report, considered.
- `Waiting for trigger` — entry zone not yet touched.
- `Entered` — user opened position.
- `Rejected` — user (or desk) decided not to take.
- `Expired` — opportunity passed without trigger.
- `TP1 hit` / `TP2 hit` / `TP3 hit`
- `Invalidated` — invalidation level was hit.
- `Reviewed` — post-trade review written.

Status transitions are forward-only. Once `Invalidated` or `Reviewed`, do not change back.

## When an idea moves between folders

- **Potential → Executed**: when user takes the trade. Copy (don't move) the file to `Executed_Trades/` and apply the `Executed_Trade_Template` overlay (Entry / Management / Exit / Review sections).
- **Watchlist → Potential**: when the watchlist monitor reports C→B/A upgrade. Copy the file with the new tier and a new filename; cross-link.
- **Anywhere → Rejected**: if the original idea died and you want to learn from it.
- **Reviewed**: once the per-idea review is written under `Reviews/`, add a backlink to the original Potential / Executed file.

## Logging when CLI is not yet available

Until `python -m src.cli log-idea-to-obsidian --idea-id ID` ships:

1. Find the idea in `data/processed/agent_outputs/<latest>_trade_idea_agent.json`.
2. Copy `obsidian_vault/11_Trade_Journal/Templates/Potential_Trade_Template.md`.
3. Fill in the fields from the JSON (raw dict has every field).
4. Save under the matching folder with the proper filename.
5. Cross-link to `data/reports/{kind}/...md`.

## Don'ts

- Don't duplicate a single idea across multiple folders without cross-linking.
- Don't log every idea — C-tier without trigger is noise.
- Don't fabricate fields from the template if the data isn't there. Leave blank or `n/a`.
- Don't commit secrets or full raw JSON dumps with API tokens into the vault.

## Active links and cross-references

Use `[[Name]]` for vault links. Use full paths for code/reports. Example:

```
Source report: data/reports/intraday/2026-05-23_08-45_intraday_report.md
Source agent dump: data/processed/agent_outputs/20260523-084500_trade_idea_agent.json
Vault rules: [[Intraday_Mode]], [[Score_Caps]]
```
