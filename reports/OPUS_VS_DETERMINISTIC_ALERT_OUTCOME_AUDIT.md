# Opus vs Deterministic Alert Outcome Audit (PART 4)

**Date:** 2026-06-14 · Read-only.

## 1. Does Opus create Telegram alerts?

**No.** Verified by grep across all of `src/`. The LLM (Opus) is used in two places:

1. **Trade-idea agent** (`src/agents/trade_idea_agent.py`) — calls the LLM to turn report context into trade ideas. Output goes to `proposed_signals` (DB) and `data/processed/agent_outputs/*.json` (file). **No Telegram call.**
2. **Stocks trade-idea agent** (`src/stocks/agents/trade_idea_agent.py`) — analogous for stocks. Output goes to DB + file. **No Telegram call.**

Telegram is then triggered downstream by the **deterministic supervisor** (crypto) or the **deterministic stocks monitor** (stocks). The supervisor / monitor reads the `proposed_signals` row and applies its own template (`_format_idea_alert` for crypto, `format_stocks_alert` for stocks). Those are pure-Python template renderers; they do not call back into the LLM.

## 2. Does Opus change tier / score / routing?

**No.** Tier and score are assigned by the scoring agent (`src/agents/scoring_agent.py` for crypto, `src/stocks/agents/scoring_agent.py` for stocks) based on deterministic rules. Opus produces the *raw* idea (entry / stop / TP / thesis). The scorer then attaches tier and score. Opus cannot retroactively change a tier.

## 3. Opus alert timing — before or after deterministic signal?

**Opus alerts as such do not exist.** Opus produces a trade-idea JSON BEFORE the row hits `proposed_signals`. The Telegram alert (crypto setup or stocks setup) fires AFTER `proposed_signals` is written. So in lifecycle order:

```
LLM(Opus) → trade-idea JSON → scoring/agents → proposed_signals row → deterministic Telegram template
```

There is no LLM-callback after the Telegram send. The message body MAY include a snippet of LLM-produced thesis text (template 1 includes the thesis line), but the *decision to send* and the *template wording* are all deterministic.

## 4. Outcome comparison — "Opus-reviewed" vs "non-Opus-reviewed"

Every A/B signal in the current system goes through the LLM trade-idea agent. There is no parallel "deterministic-only" signal path that bypasses the LLM. So a clean Opus-vs-non-Opus comparison is **structurally impossible with the current data**.

## 5. Practical conclusion

**The "Opus vs deterministic" framing is a false dichotomy in this codebase.** Every actionable trade idea is co-produced: LLM writes the raw idea, deterministic scorer / agent / monitor decides whether and how to alert.

**If the operator sees a Telegram that "looks Opus-style"** (long thesis, narrative reasoning), it's almost always the crypto setup template — the thesis line happens to include LLM-generated narrative. If the operator sees a Telegram that "looks like a trade trigger" (short, structured, `[PAPER ENTRY]` header), it's the paper-entry template.

## 6. Why might the user perceive there to be separate Opus alerts?

Plausible reasons:
1. The crypto setup template uses Markdown formatting (`*bold*`) that looks more conversational than the bracketed plain-text stocks/paper-entry templates.
2. Operator audit summaries (`[TP/STOP CATEGORY AUDIT]` etc.) sent directly via `notifier.send()` from interactive sessions can read as commentary — those *are* "LLM-style" because I composed them, but they are not trade signals.
3. Enriched-review skill / `obsidian_vault/15_LLM_Context/` produce **markdown reports**, not Telegram messages.
