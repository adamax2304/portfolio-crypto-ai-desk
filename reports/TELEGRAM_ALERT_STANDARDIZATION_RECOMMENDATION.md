# Telegram Alert Standardization Recommendation (PART 6)

**Date:** 2026-06-14 · **Status:** RECOMMENDED — not implemented yet.

This document proposes a single, clean standard for every Telegram alert. Implementation would touch 3 template renderers in the codebase; the changes are minor and additive (operator can opt-out by reverting one constant). **No scoring / TP-SL / routing / sizing change.**

---

## 1. Standard headers (REQUIRED on every alert)

| Header | When |
|---|---|
| `[SETUP — WAITING FOR ENTRY]` | Crypto/stocks scanner produces a new A/B idea; entry hasn't triggered yet. |
| `[SETUP — ENTRY CHANGE]` | Stocks monitor signals zone moved. |
| `[SETUP — TIER UPGRADE]` | Stocks monitor upgrades C→B or B→A. |
| `[SETUP — SCORE IMPROVEMENT]` | Stocks monitor signals score bump. |
| `[SETUP — INVALIDATION CHANGE]` | Stocks monitor signals stop level changed. |
| `[SETUP — CANCELLED]` | Pending revalidator marks `stale_before_entry` / `entry_moved_away`. |
| `[PAPER ENTRY — TRIGGERED]` | Tracker sees waiting → entry_triggered=1 transition. |
| `[CLOSE — TP1 / TP2 / TP3 / STOP / EXPIRED]` | Tracker sees trade closed. |
| `[OPERATOR SUMMARY — NOT A TRADE]` | Manual audit/digest sent by operator. |
| `[DAILY SUMMARY]` | Scheduled end-of-day rollup. |

## 2. Required fields per actionable alert (SETUP, PAPER ENTRY, CLOSE)

| Field | Source |
|---|---|
| `Type` (one of the headers above) | template constant |
| `signal_id` | `proposed_signals.signal_id` |
| `source` | module path that produced the message |
| `status` (waiting / triggered / closed) | `signal_outcomes.final_outcome` or `proposed_signals.status` |
| `Symbol` | `proposed_signals.symbol` |
| `Direction` | `proposed_signals.direction` |
| `Playbook` | `label_for(signal).playbook` |
| `Tier / Score` | `proposed_signals.tier / score` |
| `Entry` / `Stop` / `TPs` | `proposed_signals.entry_low/high/stop_loss/tp1/tp2/tp3` |
| `Size weight` (e.g. `1.0×`) | `size_decision(signal).weight` |
| `Risk flags` (list of strings) | `_risk_flags(signal)` from paper-entry module |
| `Manual shadow disclaimer` | constant: *"Manual shadow only — system did not place a real order."* |
| `Generated by:` (module path) | template metadata |
| TradingView URL | `_tradingview_link()` |

## 3. Required fields per non-actionable alert (operator summaries, daily summaries)

| Field | Source |
|---|---|
| `Type` header that begins `[OPERATOR SUMMARY ...]` or `[DAILY SUMMARY ...]` | template constant |
| Explicit `NOT ACTIONABLE — commentary / summary only` line at the top | template constant |
| Body content as today | per use case |
| `No paper entry recorded.` line at the bottom | template constant |

## 6. Trivial / additive changes we CAN make NOW

Per the audit spec, only "trivial and additive" changes are allowed without explicit operator approval. The following 2 changes meet that bar:

### Change A: Prefix operator summary script messages with `[OPERATOR SUMMARY — NOT A TRADE]`
This affects only scripts/audit/build commands that send Telegram directly. Doesn't touch agent code. **SAFE to implement** in the audit framework.

### Change B: Add a one-line `signal_id:` footer to the paper-entry alert body
The paper-entry template already includes `signal_id` in the payload; promoting it to the visible body is a 2-line template edit. **SAFE** — doesn't change any decision logic.

The operator should decide whether to apply A and B now. Neither is implemented in this audit pass.

## 7. What this report does NOT do

- Does not modify any template renderer.
- Does not change `signal_alerts` / `watchlist_alerts` schemas.
- Does not introduce new alert types.
- Does not restart the scheduler.
- Does not change scoring, routing, sizing, or TP/SL.
