## 2. Confusing patterns observed

### Confusion 1: Crypto setup alert looks like an entry
Template 1 reads:
```
*B-tier* LONG *ZEC/USDT*
score `74.2` | mode `swing` | conf `medium`
focus `binance` | data `medium`
setup: pullback
Entry: 42.00 - 42.30
Stop: 40.80
TP: 43.2 / 44.5 / 46.0

[thesis text from LLM]
```
The user sees a tier, a direction, a symbol, and an entry zone — looks like a trade signal. There is **no explicit indication** that this is a setup, not an entry. **High confusion risk.**

### Confusion 2: Operator audit summaries look like alerts
When I send `[TP/STOP CATEGORY AUDIT]` or `[CURRENT STATE / MANUAL SHADOW]` directly via `notifier.send()`, the user receives a Telegram that may be perceived as system commentary. Because no DB row is created, these don't appear in any per-signal audit. **Medium confusion risk** — they are clearly summary-shaped, but the user has flagged uncertainty about Opus-style messages.

### Confusion 3: Paper-entry dry-run rows
When `--paper-entry-dry-run` is on, a `signal_alerts` row is recorded with `telegram_status='dry_run'`. The audit / dashboard shows "paper-entry alert sent" because the row exists, but the user's phone never received it. **Low confusion risk** in production (dry-run is rarely used outside validation), but the dashboard cockpit should distinguish.

### Confusion 4: Stocks setup sub-types collapse in the visible message
A `tier_upgrade` alert and a `score_improvement` alert have the same visual bracket header in the Telegram message; only the structured `alert_type` column distinguishes them. The operator reading on a phone cannot easily tell which sub-type fired. **Medium confusion risk** for power users.

### Confusion 5: No "close / outcome" Telegram
When a paper trade closes (win / loss / expired / stop), there is **no Telegram notification**. The operator must check the dashboard or the journal. This is a coverage gap, not a clarity bug, but it contributes to the user's sense of "I don't know what state the system is in."

## 3. Template-by-template recommendations (NOT IMPLEMENTED — research only)

### (1) Crypto setup
**Current:**
```
*B-tier* LONG *ZEC/USDT*
score `74.2` | mode `swing` | conf `medium`
...
```
**Recommended:**
```
[SETUP — WAITING FOR ENTRY] CRYPTO ZEC/USDT LONG
Playbook: crypto_swing_narrative_rs_momentum
Tier/Score: B / 74.2 · Mode: swing
Entry: 42.00 - 42.30
Stop: 40.80
TP: 43.2 / 44.5 / 46.0
Size if entered: 1.0x — primary cohort

Why: [thesis line]

Status: not actionable yet. System will send a [PAPER ENTRY] message
when price reaches the zone. No real order will be placed.

Generated by: src/agents/supervisor.py::_format_idea_alert
```

### (2) Stocks setup
**Current** (varies by alert_type):
```
[STOCKS] LONG AAPL  B-tier ... [SETUP]
[New signal] [Entry change] [Score improvement] ...
```
**Recommended** prefix the visible message with the explicit sub-type:
```
[STOCKS SETUP — NEW SIGNAL] AAPL LONG ...
[STOCKS SETUP — ENTRY CHANGE] AAPL LONG ...
[STOCKS SETUP — SCORE IMPROVEMENT] AAPL LONG ...
```

### (3) Paper-entry — already good
Keep as-is. Already has all 5 clarity properties.

### (4) Operator summary
**Current:** `[TP/STOP CATEGORY AUDIT]`, `[CURRENT STATE / MANUAL SHADOW]`.
**Recommended:** prefix with `[OPERATOR SUMMARY — NOT A TRADE]`:
```
[OPERATOR SUMMARY — NOT A TRADE]
TP/STOP CATEGORY AUDIT
...
```

## 4. Missing alert types

| Missing | Recommended template |
|---|---|
| Close / outcome notification | `[CLOSE] CRYPTO ZEC/USDT LONG — TP1 hit at 43.2 (+1.0R sized) — manual shadow only` |
| Stale_before_entry / entry_moved_away | `[SETUP — CANCELLED] CRYPTO ZEC/USDT LONG — entry zone moved away; do NOT manual-fill` |
| Daily summary | `[DAILY SUMMARY 2026-06-14] open: 2; closed today: 4; raw R: +1.5; sized R: +2.0` |

## 5. Top 3 priority changes

1. **Add explicit header to crypto setup template** — eliminates the single biggest confusion ("looks like a trade trigger").
2. **Add `[OPERATOR SUMMARY — NOT A TRADE]` tag** to operator-sent summaries — distinguishes from system alerts.
3. **Add a close/outcome notification** — the user has explicitly mentioned they cannot always watch the dashboard.

These are documented but **not implemented in this audit pass**. See [TELEGRAM_ALERT_STANDARDIZATION_RECOMMENDATION.md](TELEGRAM_ALERT_STANDARDIZATION_RECOMMENDATION.md) for the full standard.
